Source file on the server

Calculation method
timestamp obtains the timestamps of running-service samples. max_over_time selects the latest observed successful timestamp over one day with a one-minute step. Subtracting it from time() gives the time since running was observed. A stopped-service fallback adds the synthetic value 86400. Another branch combines a service seen within 30 minutes with the last successful scrape time while the exporter is down. Not every branch measures the actual service outage duration.
Output unit and interpretation
Seconds; some branches use a fallback value rather than a measured outage duration.
Direct input metrics
up; windows_service_state
Direct recording-rule dependencies
None; this query reads source metrics directly.

Recording Rules

What is a recording rule? Prometheus evaluates a PromQL query at a configured interval and stores its result under a new metric name. Alerts and later queries can reuse that result; a recording rule does not send notifications itself. These rules run inside Prometheus against stored time series, not as separate SQL statements or operating-system commands. For example, rate(mssql_transactions[5m]) runs every 30 seconds and stores the five-minute average transaction rate as mssql:transactions_per_second:rate5m. Here 5m is the calculation window and 30s is the evaluation interval.

Rules in each group are evaluated in order, so a later rule in the same group can use an earlier result. Synchronization across independent groups is not guaranteed. Output series retain the labels produced by the query and use the recording-rule metric name. The 15-, 30- and 60-second intervals below come from the original configuration snapshot, not from rule names. The data was not refreshed for this document.

Reading the formula: rate calculates counter rates with reset handling; deriv estimates the linear slope of a gauge. Comparisons without bool remove nonmatching series and preserve matching values, rather than returning 0/1. on specifies matching keys, group_left imports right-hand labels, without removes aggregation dimensions, and label_replace creates or changes a label. Missing output differs from zero. Units are interpreted from formulas and metric names; individual collector contracts, actual labels and counter/gauge types were not revalidated for this edition.
